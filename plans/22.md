## Goal
Make all store-backed read endpoints acquire `store.lock` while accessing in-memory data, preventing races with concurrent writes without changing API responses or screening rules.

## Files to change
- `app/routers/alerts.py`
- `app/routers/transactions.py`
- `app/routers/watchlist.py`
- `tests/test_alerts.py`
- `tests/test_transactions.py`
- `tests/test_watchlist.py`

## Steps
1. Identify every route that reads `store.alerts`, `store.results`, or `store.watchlist`.
2. Wrap alert listing and lookup reads in `store.lock`.
3. Wrap transaction-result lookup reads in `store.lock`.
4. Wrap watchlist listing reads in `store.lock`.
5. Preserve existing filtering, ordering, response models, and error behavior.
6. Add focused regression coverage for read endpoints while retaining existing fixture and synthetic-data conventions.
7. Run `uv run pytest -v`.

## Tests to add
- `test_list_alerts_reads_are_lock_protected` — proves alert listing remains available through the locked store path.
- `test_get_alert_reads_are_lock_protected` — proves alert lookup preserves the existing response and not-found behavior.
- `test_get_screening_result_reads_are_lock_protected` — proves transaction lookup remains correct.
- `test_list_watchlist_reads_are_lock_protected` — proves watchlist listing remains correct.

## Success criteria
- All store-backed GET routes hold `store.lock` while reading shared state.
- Existing alert filters and ordering are unchanged.
- Existing 200 and 404 responses remain unchanged.
- Screening scores, decisions, and alert creation behavior are unchanged.
- `uv run pytest -v` passes.

## Risks
- Locking reads could expose deadlocks if a route performs nested store operations.
- Returning mutable store models after releasing the lock could still allow concurrent mutation during serialization.
- Incorrect lock scope could alter alert ordering or filter results.

## Rollback / escalation
Revert the implementation PR to restore the previous read paths; no data migration is required. Escalate if concurrency testing reveals deadlocks, response inconsistencies, or any impact to screening and alert decisions.
