## Goal
Move the screening constants and `RULES` unchanged from `app/screening.py` into `app/rules.py`, and import them into the screening module. Preserve `screen()`’s signature and behavior.

## Files to change
- `app/rules.py`
- `app/screening.py`
- `tests/test_screening.py`

## Steps
1. Add `app/rules.py` with the existing constants and `RULES` definitions, preserving their values, descriptions, scores, and ordering.
2. Update `app/screening.py` to import those definitions from `app.rules` without changing screening logic or `screen()`’s signature.
3. Add a focused test pinning every moved constant and every rule's id, description and score.

## Tests to add
- `test_rules_constants_unchanged` — pins every moved value: `HIGH_RISK_COUNTRIES == {"XQ", "XR", "ZZ"}`, `LARGE_AMOUNT == Decimal("7500")`, `ROUND_AMOUNT_STEP == Decimal("1000")`, `NAME_MATCH_THRESHOLD == 0.85`, `REVIEW_THRESHOLD == 50`, and `RULES` as ordered (id, description, score) tuples: `WATCHLIST_NAME` 70, `HIGH_RISK_COUNTRY` 40, `LARGE_AMOUNT` 20, `ROUND_AMOUNT` 10.

## Success criteria
- All moved constants retain their existing values.
- `app.rules.RULES` exposes the same rule IDs and scores: `WATCHLIST_NAME` 70, `HIGH_RISK_COUNTRY` 40, `LARGE_AMOUNT` 20, `ROUND_AMOUNT` 10.
- `app.rules.REVIEW_THRESHOLD` equals 50, and `test_rules_constants_unchanged` pins all six moved definitions.
- `from app.screening import RULES` (used by `app/routers/watchlist.py`) still works.
- `screen()` retains its existing signature and behavior.
- Existing tests pass unmodified, and the new test passes.

## Risks
- An omitted or altered rule definition could change screening decisions or alert scores.
- Incorrect imports could break callers that use `app.screening` definitions: `app/routers/watchlist.py` imports `RULES` from `app.screening`, so `screening.py` must keep exposing it.
- Expected effect on screening decisions and alerts: **none**. Proof: `test_rules_constants_unchanged` pins every value, and the existing suite passes unmodified. Existing tests alone don't prove it: they use amounts like 7600.10, 8000 and 9000, so a changed `LARGE_AMOUNT` would pass them.

## Rollback / escalation
Revert the change if tests fail or screening behavior changes. Escalate to a human reviewer if any threshold, score, or screening decision differs from the existing behavior. Checklist §4 (screening rules) requires a second reviewer before `plan-approved`; in this solo repo that requirement is documented, not met.

## Evidence to attach
- Test output showing the full suite passes.
- Diff showing definitions moved unchanged and `screen()`’s signature preserved.

## Out of scope
- Changing thresholds, scores, rule names, descriptions, or screening behavior.
- Changing callers.
- `infra/` and `.github/`.
