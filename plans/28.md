## Goal
Add tests covering the requested amount, country, and high-risk-country boundaries. Keep changes limited to tests; if a test exposes a bug, mark it `xfail` and open a separate issue rather than changing application code.

## Files to change
- `tests/test_transactions.py`
- `tests/test_screening.py`

## Steps
1. Add transaction endpoint tests for zero and negative amounts, three-decimal amounts, and invalid lowercase or three-letter country codes.
2. Add screening tests for the `LARGE_AMOUNT` and `ROUND_AMOUNT` boundaries.
3. Add screening tests confirming a high-risk beneficiary country triggers a hit and the same high-risk country on both sides produces one hit.
4. If any test reveals a bug, mark that test `xfail` and report the bug for a separate issue; do not change `app/`.

## Tests to add
- `test_screen_rejects_zero_amount` — zero amount returns 422.
- `test_screen_rejects_negative_amount` — negative amount returns 422.
- `test_screen_rejects_amount_with_three_decimal_places` — `0.001` returns 422.
- `test_amount_below_large_amount_does_not_trigger_large_amount` — `7499.99` has no `LARGE_AMOUNT` hit.
- `test_amount_at_large_amount_triggers_large_amount` — `7500.00` has a `LARGE_AMOUNT` hit.
- `test_round_amount_triggers_round_amount` — `1000` has a `ROUND_AMOUNT` hit.
- `test_amount_below_round_amount_does_not_trigger_round_amount` — `999.99` has no `ROUND_AMOUNT` hit.
- `test_screen_rejects_lowercase_country` — lowercase country code returns 422.
- `test_screen_rejects_three_letter_country` — three-letter country code returns 422.
- `test_high_risk_beneficiary_country_triggers_one_hit` — a high-risk beneficiary country produces one `HIGH_RISK_COUNTRY` hit.
- `test_same_high_risk_country_on_both_sides_counts_once` — the same high-risk country on both sides produces one `HIGH_RISK_COUNTRY` hit.

## Success criteria
- Each acceptance boundary has a named test.
- Valid boundary amounts produce only the expected rule hits.
- Invalid amounts and country codes return HTTP 422.
- Any test-exposed bug is marked `xfail`; no application code is changed.

## Risks
- An incorrect assertion could misrepresent existing screening behavior; verify hit IDs and counts against the stated thresholds.
- Country validation tests should cover both transaction country fields where appropriate.

## Rollback / escalation
Revert the test-only changes if they are incorrect. Escalate any discovered application bug as a separate issue; escalate any proposal to alter screening rules, scores, or thresholds to a human reviewer.

## Evidence to attach
- Test output showing the added tests’ results.
- A CI run link confirming the test suite passes.

## Out of scope
- Any changes under `app/`.
- `infra/`.
- `.github/`.
- Changes to screening rules, scores, thresholds, or application behavior.
