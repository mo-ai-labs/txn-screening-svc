## Goal
Add tests covering the requested amount, country, and high-risk-country boundaries. Keep changes limited to tests; if a test exposes a bug, mark it `xfail` and report it for a separate issue rather than changing application code.

## Files to change
- `tests/test_transactions.py`
- `tests/test_screening.py`

## Steps
1. Add transaction endpoint tests for zero and negative amounts, and three-letter country codes on both country fields.
2. Add screening tests for the `LARGE_AMOUNT` and `ROUND_AMOUNT` boundaries.
3. Do not add or rename tests for cases already covered (see *Tests to add*); never reuse an existing test function name.
4. If any test reveals a bug, mark that test `xfail` with the reason, and list the bug in the PR description so a human opens the separate issue; do not change `app/`.

## Tests to add
- `test_screen_rejects_zero_amount` — zero amount returns 422.
- `test_screen_rejects_negative_amount` — negative amount returns 422.
- `test_amount_below_large_amount_does_not_trigger_large_amount` — `7499.99` has no `LARGE_AMOUNT` hit.
- `test_amount_at_large_amount_triggers_large_amount` — `7500.00` has a `LARGE_AMOUNT` hit.
- `test_round_amount_triggers_round_amount` — `1000` has a `ROUND_AMOUNT` hit.
- `test_amount_below_round_amount_does_not_trigger_round_amount` — `999.99` has no `ROUND_AMOUNT` hit.
- `test_screen_rejects_three_letter_originator_country` — `XQZ` as originator country returns 422.
- `test_screen_rejects_three_letter_beneficiary_country` — `XQZ` as beneficiary country returns 422.

Already covered by existing tests (keep unchanged, do not duplicate):
- Three decimal places → `test_screen_rejects_amount_with_more_than_two_decimal_places`
- Lowercase country → `test_screen_rejects_lowercase_originator_country`, `test_screen_rejects_lowercase_beneficiary_country`
- High-risk country on the beneficiary only → `test_high_risk_country_alone_is_below_threshold`
- Same high-risk country on both sides counts once → `test_same_high_risk_country_on_both_sides_counts_once`

## Success criteria
- Every acceptance line in #28 maps to a named test: new or listed as already covered.
- Valid boundary amounts produce only the expected rule hits.
- Invalid amounts and country codes return HTTP 422.
- No test function name is defined twice in a module; the existing tests still run.
- Any test-exposed bug is marked `xfail` and listed in the PR description; no application code is changed.

## Risks
- An incorrect assertion could misrepresent existing screening behavior; verify hit IDs and counts against the stated thresholds.
- Redefining an existing test name in the same module silently replaces the original, so pytest runs only the new one; existing coverage could drop without any failure.

## Rollback / escalation
Revert the test-only changes if they are incorrect. Escalate any discovered application bug as a separate issue opened by a human; escalate any proposal to alter screening rules, scores, or thresholds to a human reviewer.

## Evidence to attach
- Test output showing the added tests’ results and the total count (existing tests not reduced).
- A CI run link confirming the test suite passes.

## Out of scope
- Any changes under `app/`.
- `infra/`.
- `.github/`.
- Changes to screening rules, scores, thresholds, or application behavior.
