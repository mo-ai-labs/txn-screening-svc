## Goal
Add `POST /transactions/screen/bulk` to validate and screen batches of 1–100 transactions, returning stored results in input order and raising alerts as the single-transaction endpoint does.

## Files to change
- `app/models.py`
- `app/routers/transactions.py`
- `tests/test_transactions.py`

## Steps
1. Add a Pydantic request model that constrains the `transactions` list to 1–100 `TransactionIn` items.
2. Add the bulk route; reuse `screen()` for each item and store each result and any corresponding alert under the store lock.
3. Add focused tests for batch decisions, order, validation boundaries, atomic rejection of invalid input, and retrieval of returned transaction IDs.

## Tests to add
- `test_screen_bulk_preserves_order_and_creates_alert_for_review`: three transactions produce two clear results, one review result, preserve input order, and create one alert.
- `test_screen_bulk_rejects_empty_transactions`: an empty list returns 422.
- `test_screen_bulk_rejects_more_than_100_transactions`: 101 items return 422.
- `test_screen_bulk_rejects_invalid_item_without_storing_results`: an invalid item returns 422 and leaves results and alerts unchanged.
- `test_get_screening_result_for_each_bulk_transaction`: every returned transaction ID can be retrieved.

## Success criteria
- A valid batch of 1–100 transactions returns 201 with results in input order.
- Each item is screened using `screen()` and stored; review items each have an alert.
- Empty and 101-item batches return 422.
- Any invalid item returns 422 without storing results or alerts.
- `GET /transactions/{id}` returns each bulk result.
- `uv run pytest -v` passes.

## Risks
- Incorrect list bounds or request-model validation could accept invalid batch sizes.
- Partial writes could occur if validation is performed after processing begins; validate the complete request before entering the storage loop.
- Changes to screening rules or thresholds could alter decisions; those are out of scope.

## Rollback / escalation
Revert the implementation commit to remove the bulk route and request model. Escalate to a human reviewer if implementation requires changing screening rules, scores, or thresholds.

- Test output covering batch decisions, ordering, validation, storage atomicity, and retrieval.

## Out of scope

- `.github/`
